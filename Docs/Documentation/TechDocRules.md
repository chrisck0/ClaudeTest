# 기술문서 작성 규칙

> 기능의 구현 내용을 설명하는 기술문서를 작성할 때의 규칙.
>
> 문서 작성 양식은 `@Docs\Template\TechDocTemplate.md` 를 참고.
>
> 작성 시점과 승인 절차는 이 문서에 적지 않는다. `Docs\Claude\WorkflowRules.md`의 `6. 문서 / 다이어그램 반영`을 따른다.

---

## 1. 문서 위치와 이름

- 기술문서는 `Docs/Tech/` 폴더 바로 아래에 둔다. 하위 폴더로 분류하지 않는다.
- 파일 이름은 문서가 다루는 시스템의 이름을 영문 PascalCase로 적는다. (예 : `Player.md`)

## 2. 작성 단위

- 문서 하나는 시스템 하나를 다룬다.
- 시스템은 `Assets/Scripts/` 바로 아래의 폴더 하나를 말한다. (예 : `Assets/Scripts/Player/` → `Player.md`)
    - 스크립트를 어느 폴더에 두는지는 `Docs\Code\CodeConvention.md`의 `6. 스크립트 폴더`를 따른다.
- 새 기능의 스크립트가 이미 문서가 있는 폴더에 들어가면 그 문서에 추가하고, 문서가 없는 폴더에 들어가면 새 문서를 만든다.

## 3. 문서 구성

- 문서는 독자가 시스템의 구조를 파악하고, 동작 흐름과 설계 이유를 이해할 수 있도록 작성한다.
- 문서는 `Docs\Template\TechDocTemplate.md`의 섹션 구성을 따르며, 각 섹션에는 아래 내용을 적는다.

| 섹션 | 적는 내용 | 적지 않는 내용 |
| --- | --- | --- |
| 개요 | 시스템이 하는 일(2 ~ 3줄), 관련 프리팹, 관련 입력 | 클래스별 상세 설명 |
| 구조 | 클래스와 그 역할, 클래스 사이의 관계 | 실행 순서 |
| 동작 흐름 | 실행 순서, 상태 변화 | 클래스 역할 설명의 반복 |
| 설계 결정 | 이렇게 구현한 이유, 검토했지만 고르지 않은 대안 | 브리핑이나 사용자의 결정에 근거가 없는 추측 |

## 4. 구현과의 대응

- 클래스는 클래스명과 스크립트 경로를 함께 적는다. (예 : `PlayerJump` (`Assets/Scripts/Player/PlayerJump.cs`))
- 메서드명은 적지 않는다.
- 씬 / 프리팹은 프리팹 이름만 적는다. Hierarchy 경로는 적지 않는다. (예 : `PFB_Player`)
- 코드 원문은 문서에 옮겨 적지 않는다.

## 5. 다이어그램

- 다이어그램은 mermaid로 작성해 문서 안에 넣는다. 별도 파일이나 이미지 파일로 두지 않는다.
- 아래 경우에만 다이어그램을 그리고, 그 외에는 글로 설명한다.

| 경우 | mermaid 형식 |
| --- | --- |
| 상태 전이가 있을 때 | `stateDiagram-v2` |
| 클래스 사이에 참조, 이벤트 관계가 있을 때 | `classDiagram` |
| 여러 클래스를 거치는 실행 흐름이 있을 때 | `sequenceDiagram` 또는 `flowchart` |
