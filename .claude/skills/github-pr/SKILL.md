# Github PR 등록

> 워크플로우 `8. PR` 단계를 수행하는 스킬.
>
> 이 스킬은 **절차와 멘트 규격**만 정의한다. 섹션별 작성 규칙은 아래 원본 문서를 읽고 따른다. (규칙의 단일출처 유지)

## 절차

1. **권유** : 사용자가 Push 완료를 알리면 [권유 멘트](#1-권유-멘트)로 권유한다.
   - Push 완료 전이면 이 스킬을 중단하고 `7. Commit / Push` 안내로 돌아간다.
2. **병합 대상 확인** : [질문 멘트](#2-병합-대상-질문-멘트)로 병합 대상 브랜치를 질문한다. 답을 받지 못하면 작성을 거부한다.
3. **초안 작성** : 참조 문서를 읽고 양식에 맞춰 초안을 작성한다.
   - 연관 Issue가 있으면 `gh issue view <번호>`로 `완료조건 (DoD)`를 읽어 `확인사항`에 옮긴다.
4. **승인** : [승인 멘트](#3-작성-전-승인-멘트)로 초안을 보여주고 승인을 받는다. 수정 요청 시 3번으로 돌아간다.
5. **등록** : `gh pr create`로 등록한다.
   - 등록 전 `gh auth status`로 인증 상태를, `gh pr view`로 작업 브랜치에 열린 PR이 있는지 확인한다.
   - Title은 `--title`로 전달하고, 본문에서는 `# [Title]` 줄을 제외한다.
   - 본문은 세션 임시(scratchpad) 디렉터리에 UTF-8 파일로 저장한 뒤 `--body-file`로 전달한다.
   - Label이 없으면 `gh label create`로 먼저 생성한다. 신규 생성 여부는 4번 승인 멘트에 표시해 승인받은 경우에만 생성한다.
6. **안내** : [완료 멘트](#4-등록-완료-멘트)로 PR 번호를 알린다.

### 예외 처리

- 아래 경우에는 임의로 재시도하거나 우회하지 않고, [실패 멘트](#5-등록-실패-멘트)로 보고한 뒤 사용자의 지시를 기다린다.
  - `gh` 인증이 되어 있지 않은 경우 : 사용자에게 `! gh auth login` 실행을 안내한다.
  - 작업 브랜치에 이미 열린 PR이 있는 경우 : 새로 만들지 않고 기존 PR의 URL을 알린다.
  - `gh label create`, `gh pr create`가 실패한 경우 : 오류 메시지를 그대로 전달한다.

## 멘트 규격

- 각 멘트는 아래 형식만 사용하고, 형식 밖의 설명을 덧붙이지 않는다.
- `[ ]` 안은 한 줄로 작성한다.

### 1. 권유 멘트

```markdown
**PR 등록 권유**
- 작업 브랜치 : [현재 브랜치]
- 변경 파일 : [N]개
- 연관 Issue : [#번호 / 없음]
- 예상 Label : [Label]

PR을 작성할까요?
```

### 2. 병합 대상 질문 멘트

```markdown
병합 대상 브랜치를 알려주세요. (예 : `Develop`, `main`)
```

### 3. 작성 전 승인 멘트

```markdown
**PR 초안**
- 병합 : [작업 브랜치] → [대상 브랜치]
- Label : [Label] [(신규 생성) / (기존)]
- 연관 Issue : [#번호 / 없음]
- 미확인 항목 : [N]개 (특이사항에 사유 기재)

(PRTemplate 양식의 본문 전체)

이대로 등록할까요?
```

### 4. 등록 완료 멘트

```markdown
PR #[번호] 등록 완료 : [URL]
```

### 5. 등록 실패 멘트

```markdown
**PR 등록 실패**
- 단계 : [인증 확인 / 기존 PR 확인 / Label 생성 / PR 등록]
- 오류 : [오류 메시지]
- 조치 : [사용자가 할 일]
```
